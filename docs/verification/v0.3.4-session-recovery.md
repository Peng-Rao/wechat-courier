## 连续运行故障的定位与修复

用户另授权一次受控重启，微信从 PID 59532 变为 54232。重启后最初可见绑定 5/5，
第二次托盘预检又出现壳节点。原始失败报告保留于 `final-candidate-validation.json`，
不能把那一轮标为全部通过。

随后在同一 PID 中复现并观察到：Agent 仍持有会话，但实时门禁字节由 1 变成 0。
仅重复阅读器广播无效，重建 UIA COM 客户端也无效；重新写入门禁 1、回读、广播后立即恢复。
证据保留于 `retained-client-before-fix.json`。这证明了门禁漂移与恢复链路，
但未证明具体哪个微信内部操作重置了字节。

会话复用、软刷新及任务清理现在都先校验实时进程和模块身份，重新写入并回读门禁，
再广播阅读器标志。原始租约及原始阅读器状态不改变。
遇到未知字节或模块身份变化，刷新和退出清理均拒绝写入，保留租约供安全恢复。
广播失败则尝试回滚原始状态。

清理动作日志原先把失败字典记为成功，已修正结果、后置条件和错误码，且不记录账号或清理明文。
门禁漂移也复现过清理 UIA 身份不可见；修复后源码 8 次及最终包 5 次预检均未复现。
没有断言更早缺少诊断的每一次失败必定都是同一原因。

## 限制

- 仅支持微信 4.1.13.65，不保证所有壳节点状态都可免重启恢复。
- 真实消息恰好一次的证据来自前述 `7c38...` 候选包；最终 `6f8f...` 包只做无发送复验，
  不冒充最终指纹重新发送的证据。发送状态机在这些候选包之间没有修改。
- 出于共享租约安全考虑，其他 Windows 会话中的 Agent 仍会阻止本 Agent 启动。
  独占锁本身为会话级；不同会话并行运行不在本版支持范围内。
- QML runner 仍有 Qt5Compat 和测试替身字段缺失警告，无失败用例。
